# uē-tôo Logo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the uē-tôo logo files and put them in the README, the examples app and the docs site.

**Architecture:** Hand-written SVG masters in `ue-too/brand/` are the source of truth; PNG/ICO files are exported from them once and committed. Generation scripts live in the scratchpad, not the repo (the logo rarely changes; any SVG renderer can re-export). The docs site gets copies of the web assets in one shared public folder used by every version build.

**Tech Stack:** SVG, Playwright Chromium (pre-installed) for rasterizing, Pillow for ICO, fontTools (scratch-only `pip install`) for outlining the wordmark, VitePress config.

**Spec:** `docs/superpowers/specs/2026-11-11-logo-design.md`

## Global Constraints

- Colors: brackets/wordmark `#1F2A1C` (light), `#EEF2EA` (dark); pen line `#5D8C3E` (light), `#8BC563` (dark).
- Geometry: the spec's path data, verbatim; round caps and joins; no dot at the start of any line.
- Wordmark: "uē-tôo", Nunito ExtraBold (800), letter spacing −0.01em, as outlines (no `<text>` anywhere).
- Commit types must not trigger a release bump: use `docs:` or `chore:`, never `feat:`/`fix:` (see CLAUDE.md, "Commit messages are the version signal").
- ue-too `docs/` is gitignored; plan/spec files need `git add -f`.

## Review Focus

- README in GitHub dark mode → the dark lockup shows (Task 3 checks the `<picture>` markup; GitHub itself can't be tested here).
- Archived docs versions (`/v0.18/`, `/v0.19/`) → logo and favicon load under their base path (Task 4 build check).
- Dark browser tab → `favicon.svg` switches to `#8BC563`; PNG/ICO fallbacks stay light green (accepted).
- No Nunito installed → lockup looks identical (Task 1: no `<text>` check).
- The line's round end at the right edge → not clipped by the mark's viewBox (Task 1 render check).
